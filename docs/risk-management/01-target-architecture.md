# معماری هدف — Enterprise Risk Management

اصل: همان ماژول و همان جدول‌ها؛ فقط گسترش افزایشی و مهاجرت امن. هیچ سامانهٔ موازی ساخته نمی‌شود.

## داده
| موجودیت | رویکرد |
|---|---|
| `rm_risks` | ستون‌های جدید: علت/رویداد/پیامد، منشأ و شناسهٔ خارجی، اثر چندبعدی (`impact_dims`)، کیلومتراژ/قطعه/ایستگاه/جبهه/پیمانکار/بستهٔ کاری، مالک پایش/تأیید، تاریخ بازنگری، ریسک مادر، وضعیت «تحقق‌یافته». امتیاز ذاتی قابل‌تغییر نیست (تریگر). |
| `rm_risk_assessments` | ستون‌های روش (کیفی/نیمه‌کمی/کمی)، مبنا، اثر چندبعدی، نوع (بازبینی/پس از اقدام)، تأییدکننده. فقط افزودنی (تریگر ضد ویرایش/حذف). |
| `rm_risk_actions` | نوع (پیشگیرانه/کاهشی/اصلاحی/اقتضایی)، خروجی، منابع، معیار تکمیل، هزینه/منفعت، زیراقدام، مسدودی، **نتیجهٔ اثربخشی** (مؤثر/نسبی/بی‌اثر) با شاهد. تکمیل اقدام امتیاز را تغییر نمی‌دهد. |
| `rm_controls`, `rm_contingency_plans`, `rm_risk_evidence`, `rm_risk_links` | کنترل‌های موجود و اثربخشی‌شان؛ برنامهٔ اقتضایی؛ شواهد؛ ارتباط ریسک–ریسک/Issue/خارجی. |
| `rm_kris`, `rm_kri_readings`, `rm_kri_events` | شاخص هشدار، قرائت‌ها (دستی/API)، تاریخچهٔ عبور از آستانه؛ تریگر وضعیت را به‌روز و درخواست بازنگری ثبت می‌کند. |
| `rm_policy`, `rm_categories` | آستانه‌های پذیرش/تحمل/ارجاع، فواصل بازنگری، برچسب مقیاس؛ دسته و زیردستهٔ قابل‌تنظیم (۱۵ دستهٔ نفت و گاز). تغییرات در `rm_config_audit` ثبت می‌شود. |
| `rm_acceptances` | پذیرش رسمی ریسک باقیمانده با مرجع مجاز (منع تأیید توسط درخواست‌کننده). |
| `rm_corporate_risks` | ریسک مادر/سازمانی؛ ریسک‌های پروژه با `corporate_risk_id` وصل می‌شوند و سوابق مستقل می‌مانند. |
| اعلان | بازاستفادهٔ `im_notif_outbox/prefs/rules` + edge function `im-notify` (قاعده‌های `rk_*`)، تولیدکنندهٔ `rm_generate_notifications()`، زنگوله از `my_notifications()`. |
| ورودی | `rm_ingest_risk(...)` ایدمپوتنت با (`external_system`,`external_id`) برای مأموریت/API؛ `ms_transfer_finding` به آن وصل می‌شود. |

## دسترسی
همان RLS مرکزی (عضو پروژه/ادمین/دامنهٔ مرکزی). نوشتن بر اساس `rm_can_edit/rm_can_manage` که اکنون نقش مرکزی را هم می‌پذیرند (`rm_central_role`). گزارش‌ها و داشبوردها فقط از طریق همین جدول‌ها (RLS) می‌خوانند؛ هوش مصنوعی فقط داده‌ای را می‌بیند که کاربر می‌بیند.

## UI
هویت بصری یکپارچه با «مدیریت موانع» (توکن‌های سامانه، `issues.css` مشترک)، نوار تب‌های رنگی، صفحات: خانه (داشبورد نقش‌محور)، رجیستر، ماتریس، اقدامات، اثربخشی، KRI، پورتفولیو، منابع و پیشنهادها، اعلان، گزارش‌ها، شاخص‌ها، تنظیمات، راهنما.

## مراحل
1. هسته: DB + رجیستر/فرم/جزئیات/ارزیابی/پاسخ/کنترل + داشبورد + اعلان.
2. پایش و یکپارچگی: KRI، اثربخشی، Issue دوطرفه، مأموریت، پورتفولیو.
3. هوشمندی: مشابه‌یابی، علل مشترک، پیشنهاد AI (در صورت وجود زیرساخت)، بانک دانش.
